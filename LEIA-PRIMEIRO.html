Instalação rápida (Windows)

  1. Instale o Python 3.9+ em python.org marcando “Add python.exe to PATH”.
  2. Dê dois cliques em DMK.bat → opção 1 Preparar ferramentas. Ele instala o PlatformIO numa pasta só do projeto (.venv). Na primeira compilação baixa os compiladores — precisa de internet.
  3. Conecte o SERVE no USB → opção 2 → escolha a placa (ESP32, ESP32‑S3 ou ESP8266) → digite a porta (ex.: COM5) → S para instalação limpa.
  4. No celular, conecte no Wi‑Fi DMK-SERVE-xxxxxx (senha 12345678). O painel abre sozinho (ou http://192.168.4.1). Configure Wi‑Fi, MQTT e troque a senha do painel.
  5. Conecte o CONTROLE no USB → opção 3. Ligue os dois perto um do outro: na primeira vez eles pareiam sozinhos e o controle já recebe o Wi‑Fi e o MQTT do SERVE.
Só uma gravação. O painel web agora vai dentro do firmware — não existe mais a etapa “uploadfs”. E a atualização pela internet atualiza firmware e painel juntos.

Parear o controle com o SERVE

O pareamento cria uma chave secreta só desses aparelhos (troca de chaves X25519). Sem ela, nenhum comando é aceito.

OndeComo
SERVESegure o botão BOOT/FLASH por 3 s e solte (abre 2 minutos). Ou no painel: Sistema → Parear controle.
Na primeira instalação (nenhum controle pareado) a janela já abre sozinha por 3 minutos.
CONTROLESegure BOMBA + LUZ juntos por 3 s. Ou no painel do controle: Parear com o SERVE.
Controle novo procura o SERVE sozinho ao ligar.

Durante o pareamento o LED azul pisca rápido e o LCD mostra PAREANDO.... O controle procura o SERVE em todos os canais Wi‑Fi (1 a 13).

Com a opção “Enviar Wi‑Fi e MQTT para o controle ao parear” (ligada de fábrica) o controle reinicia já conectado na mesma rede e broker. Os dados vão cifrados.

Botão do SERVE (BOOT/FLASH)

  • Soltar entre 3 e 30 s → pareamento
  • Segurar 30 s → ponto de acesso de configuração (como na 1.0.0)

Botões do CONTROLE

  • BOMBA ou LUZ (toque curto) → liga/desliga
  • BOMBA + LUZ por 3 s → pareamento
  • MENU: toque = próxima tela · 5 s = liga/desliga LCD · 30 s = ponto de acesso

Como o controle fala com o SERVE

1º ESP‑NOWDireto entre as placas, sem roteador, em ~20 ms. Funciona até sem internet.
2º Rede localPelo mesmo Wi‑Fi (UDP), se o ESP‑NOW não responder em 0,35 s.
3º MQTTPelo broker (como na 1.0.0), se a rede local não responder em 0,7 s.

A escolha é automática a cada comando. O SERVE continua executando tudo pela mesma fila de antes: proteção de tensão, histórico, automações e “bomba sempre desliga ao reiniciar”.

O aplicativo remoto (app/APPDMK-UNIFICADO.html) e os tópicos MQTT continuam iguais.

ESP‑NOW e canal Wi‑Fi: as duas placas precisam estar no mesmo canal. Se as duas usam o mesmo roteador, isso é automático. Se o controle não tem Wi‑Fi, ele acompanha o canal do SERVE sozinho.

Atualizar pelo GitHub (botões e servidor)

Uma vez só

  1. Crie conta em github.com e um repositório público vazio (ex.: dmk-smart).
  2. Instale o Git (git-scm.com).
  3. DMK.bat → 5 Configurar GitHub → digite seu-usuario/dmk-smart.

A cada versão nova

  1. Faça as alterações e rode DMK.bat → 6 Nova versão (SERVE, CONTROLE ou os dois — as versões são independentes).
  2. DMK.bat → 7 Publicar no GitHub. O GitHub compila as 6 placas e cria a Release com os .bin e o manifest.json (5–10 min).
  3. Abra Atualizações (DMK.bat → 8, ou http://IP-DA-PLACA/ota-mqtt), selecione as placas, Verificar e Atualizar selecionadas. Funciona de outra cidade pelo MQTT.
Cada placa baixa só o arquivo dela, confere o modelo, o SHA‑256 e nunca volta para versão anterior. No SERVE a bomba e a luz são desligadas antes de gravar. Também existe a opção instalar sozinho (o SERVE só instala com a bomba desligada).

As placas verificam novas versões a cada 6 horas. Firmware compilado pelo GitHub já vem com o repositório certo; compilado no PC usa o que está em dmk-github.txt (ou configure no painel).

O que mudou na segurança

  • ESP‑NOW e rede local cifrados e autenticados (HMAC‑SHA256 com chave do pareamento). Quadro alterado ou repetido é recusado.
  • Comando gravado não funciona depois: cada comando leva a “sessão” atual do SERVE, que muda a cada reinício e a cada 10 minutos.
  • Painel web com senha para tudo que altera algo (ligar bomba, salvar, parear, atualizar): usuário admin + senha do painel. Pelo ponto de acesso de configuração não pede (precisa do botão físico).
  • Atualização por MQTT sem enviar a senha: o painel assina cada comando (HMAC); validade de 5 minutos.
  • OTA confiável: HTTPS com certificados raiz embutidos, SHA‑256 conferido, sem downgrade.
  • Comando MQTT retido no broker é ignorado também no ESP8266.
  • Aviso no painel enquanto a senha ainda for a padrão 12345678.
Broker público: broker.hivemq.com é aberto — quem souber o tópico consegue publicar. Use um tópico difícil de adivinhar ou um broker com usuário/senha. ESP‑NOW e rede local não dependem do broker.

Perdeu um controle? Painel do SERVE → Sistema → Trocar chave e pareie de novo os controles que ficaram.

Problemas comuns

SintomaO que fazer
DMK.bat não acha a porta COMUse cabo USB de dados e instale o driver CH340 ou CP210x. Opção P lista as portas.
Gravação falhaO DMK.bat tenta de novo mais devagar. Se persistir, segure BOOT na placa quando aparecer “Connecting…”.
Controle não pareiaDeixe as placas a menos de 5 m. No SERVE solte o BOOT entre 3 e 30 s (LED pisca rápido). Se o controle estiver em outro roteador/canal, pareie antes de configurar o Wi‑Fi dele.
LED do controle com 2 piscadasEstá indo por MQTT: ESP‑NOW e rede local não responderam. Confira distância e se os dois estão no mesmo roteador.
“Nenhuma versão publicada”A Release ainda não terminou no GitHub (aba Actions) ou o repositório está privado/errado.
ESP8266 falha ao baixar do GitHubHTTPS no ESP8266 usa muita RAM. Use “Enviar arquivo .bin” no painel local com o arquivo da Release.
Painel pede usuário e senhaUsuário admin, senha do painel (a mesma da OTA; padrão 12345678 — troque!).
